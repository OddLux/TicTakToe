# Two Session Types

**Date:** 2026-06-18
**Concept:** The fundamental Type A vs Type B distinction and how to classify any given folder
**State:** ready-for-scribe

## Stream

There are two session systems coexisting in this repo and they were born for different reasons. The path prefix is the discriminator -- this is the single cleanest classification signal the SessionScrutinizer has.

**Type A = `.agents/sessions/`.** Archival. Small. Committed and tracked deliberately. Created at the END of a session by the `session-handover` skill (documented in AGENTS.md Workspace section 5). Its whole job is cold-start reconstruction: a future session reads `manifest.toml` + `crumbs.md` to rebuild context fast. Two tiers exist by design -- crumbs (skinny, default) and loaf (`--loaf`, full fat). Because it is generated by a skill, it is comparatively uniform. AGENTS.md actually describes its schema, so it has formal backing. This is the "publication" of a session.

**Type B = `.sessions/`.** Workspace. Live. Created at the START of a session as scratch+working space while the work is happening. It is richer and messier: `plans/` with raw-vs-processed plan capture, `meetings/` for council verdicts, `handovers/`, and `.knowledgeblob/` for stream-of-consciousness working memory. Crucially, AGENTS.md says NOTHING about `.sessions/` -- it has zero formal backing. It was invented during the 2026-06-18 session and exists purely as emergent convention captured in plan docs and handover notes inside the session itself.

Why do they coexist? Type A is the distilled keepsake; Type B is the kitchen it was cooked in. Type A answers "what happened and what's left"; Type B holds the raw thinking, the council debate, the rejected drafts, the plan versions. They serve genuinely different lifecycles: A is end-state and durable, B is during-work and high-churn. Nobody has merged them because the work that would do that (formalizing `.sessions/` into AGENTS.md) hasn't shipped.

What rules apply to A but not B: the `manifest.toml` + `crumbs.md`/`loaf.md` schema, the `YYYY-MM-DD_<3-word>` directory naming, the crumbs YAML frontmatter contract. These are documented. What applies to B but not A: the `__RAW_`/`vNNN` plan split, the `meetings/` and `handovers/` subfolders, the `.knowledgeblob/{agent-type}-{three-words}/` pattern. These are emergent, not documented.

For classification: SessionScrutinizer should resolve the path first. If the folder is under `.agents/sessions/`, validate against the AGENTS.md-backed Type A schema (these checks can be FAIL -- the schema is formal). If under `.sessions/`, validate against the emergent Type B conventions (these should mostly be WARN -- not yet formal). The prefix is reliable; do not infer type from folder contents, because contents overlap (both have `plans/`, both can have handovers).

## Shape so far

- Type A = `.agents/sessions/` = archival, end-of-session, skill-generated, AGENTS.md-backed, uniform.
- Type B = `.sessions/` = live workspace, start-of-session, hand-built, NO AGENTS.md backing, loose.
- Path prefix is the authoritative discriminator. Resolve path before validating.
- Type A violations can justify FAIL (formal schema); Type B violations lean WARN (emergent).
- Overlapping folder names (`plans/`, handovers) mean content-based classification is unreliable -- use the prefix.
